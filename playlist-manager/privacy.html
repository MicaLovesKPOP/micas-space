Privacy policy

Effective 25 November 2026

This policy describes the personal desktop utility Mica YouTube Playlist Manager, operated by its owner (GitHub: MicaLovesKPOP). The application uses YouTube API Services. Google's handling of information is described in the Google Privacy Policy.

Information accessed

After the owner's Google OAuth consent, the desktop application can access the authorised YouTube channel identity, playlist IDs, names, descriptions, visibility, item IDs, ordering and track/video information. It also retrieves public video metadata, such as titles, artists or uploaders, release descriptions, durations and availability restrictions. Google issues OAuth access and refresh tokens for use on the owner's computer. The application does not request the owner's Google password, read browser authentication cookies or download audiovisual content from YouTube.

Purpose and use

Information is used for owner-directed playlist organisation, recording selection, historical chart playlist preparation, duplicate checks, import verification and maintenance. Playlist writes are limited to specifically authorised actions and destinations. The app is not a public service and does not sell user data or use it for advertising. It does not use Google user data to train general-purpose AI models.

Storage and authorised assistance

OAuth configuration and tokens, playlist snapshots, cached metadata, work records and operation receipts are stored on the owner's computer. Independent chart research and listening observations are maintained separately from YouTube API metadata. Google receives the requests necessary to provide the YouTube API service. The owner may explicitly authorise remote computer assistance and ChatGPT-assisted engineering or review; only information necessary for those requested operations should be made available to authorised assistants, and credentials, tokens, unrelated playlists and private records must not be disclosed to them or published. The application is not intended for transferring Google user data to unrelated parties. Google API data must be handled in accordance with the Google API Services User Data Policy and YouTube API Services Developer Policies.

Retention and security

Access tokens and refresh tokens are retained locally only as needed for authorised access. Cached YouTube API data is subject to YouTube's applicable refresh and deletion limits: generally refresh or delete within 30 calendar days, with only the exceptions permitted by YouTube's policies. Independent historical chart information and owner-authored research can be retained separately, provided it is not retained API data. Local backups and receipts containing API data are subject to the same requirements. The application must not operate beyond the scope of consent or retain API-derived information indefinitely. Ongoing engineering includes enforcing these limits and separating independent archival evidence from API-derived metadata; these pages are not a certification of a completed compliance audit.

Revocation and deletion

The owner can stop authorising access through Google Account permissions and can request removal of locally stored data using the existing private support/contact channel. A request to withdraw authorisation or erase data is to be acted on promptly: revoke the applicable token and remove stored authorised data within the applicable policy deadlines (within seven calendar days for an in-app revocation or direct deletion request, and within 30 calendar days of revocation through Google). Revoking access or deleting local records does not itself delete playlists on YouTube. The owner controls those playlists through YouTube or a specifically authorised client. The desktop deletion and revocation workflow is being documented and validated; the app owner must perform the necessary cleanup if an automated workflow is not yet available.

This website

These static pages contain application documentation only and have no sign-in form, embedded player, analytics script or advertising. GitHub Pages hosts them and may process routine connection information under the GitHub Privacy Statement.

Questions and requests

Contact the developer via the support email displayed on the Google OAuth consent screen or through the developer's existing private contact channel. The developer profile identifies the owner. Please do not send passwords, tokens, private playlists or personal information through public GitHub issues.
